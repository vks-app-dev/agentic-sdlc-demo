## What and why
<!-- The technical work and the reason for it, e.g. "Upgrade FastAPI 0.110 → 0.115: security fix CVE-xxxx". -->
Raise the FastAPI floor in pyproject.toml from `fastapi>=0.110` to the latest release and refresh uv.lock. The lock currently pins fastapi 0.161.1, so the work is to re-lock to whatever is newest on PyPI at implementation time and to move the declared minimum to match. The aim is to stay current on security and bug fixes and to stop the declared floor lagging the real version. No user-visible behaviour changes.

## Risk and rollback
Risk: low, because the app is tiny (one /health endpoint in app/main.py, expenses package empty) and uses no deprecated FastAPI/Pydantic APIs. The only test is tests/test_health.py. Starlette or Pydantic may be bumped transitively, but nothing in the code uses them directly.
Rollback: revert the commit (pyproject.toml and uv.lock) and run `uv sync`. Nothing is deployed or migrated by this change.
Dependencies: none.
