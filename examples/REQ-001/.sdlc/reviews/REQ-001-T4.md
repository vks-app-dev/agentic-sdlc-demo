## Coverage of task / ADR security-review row (OWASP A04, 16 KiB, 413 `payload_too_large`)
- Limit is 16 KiB (16384); a body of exactly 16384 bytes is accepted and 16385 is rejected, on both the Content-Length path and the streamed path: OK, tested.
- Declared Content-Length above the limit returns 413 without calling `receive` or the app: OK (`receive_calls == 0` asserted).
- Streamed byte counting covers chunked bodies with no Content-Length and bodies longer than their declared length. Reading stops at the first chunk past the limit, and nothing is buffered: OK, tested.
- 413 uses the Q10 envelope from `app.errors.error_response` with a fixed message. Body content is never echoed or logged (tested for both paths): OK.
- Large malformed JSON gets a 413, not a 422, and the handler is never called: OK.
- Unrelated exceptions still propagate to `CatchAllMiddleware` (tested), and the T8 wiring keeps an unhandled error as a generic 500 without the secret in logs (tested): OK.

## Coder-flagged decisions
- Malformed Content-Length returns 400 `bad_request` in the envelope: agreed. `bytes.isdigit()` is ASCII-only, so `+5`, `-1`, `1.5`, `0x10`, empty and `5, 5` are all rejected. Identical repeated headers collapse through the set and are accepted (RFC 9110 permits this), while differing ones return 400. In production uvicorn's parser rejects most of these first, so this is defence in depth.
- Overly long Content-Length is treated as too large without converting to int: agreed, but see the first nit about leading zeros.
- `Connection: close` on the 413/400 responses: agreed. The unread body would otherwise desync a keep-alive connection.
- Replacing FastAPI's 400 with a 413 when the streamed total passes the limit, only if the response has not started: correct. `guarded_send` drops every message after `exceeded` until a start has gone out, so no partial 400 leaks, and there is never a second `http.response.start` (tested both ways).
- Mounting order: correct for Starlette 1.9 (`add_middleware` inserts at index 0, so the last one added is outermost). Calling BodySizeLimit, then TrustedHost, then `register_error_handlers` gives ServerError -> CatchAll -> TrustedHost -> BodySizeLimit -> ExceptionMiddleware -> router. That is what the ADR needs: disallowed hosts are rejected before any body is read, and CatchAll wraps everything. T8 must follow the module docstring.

## Non-blocking
- [nit] app/middleware.py:88-90: the length guard looks at `value.lstrip(b"0")`, but `int(value)` then converts the original string. A Content-Length made of thousands of leading zeros plus a small number (e.g. `b"0"*5000 + b"1"`) gets past the guard and reaches `int()` with more than 4300 characters. CPython's int-string-conversion limit should then raise `ValueError`, which would surface as a 500 through CatchAll instead of a 400/413. This is not verified (the probe was denied). It is unlikely to be reachable behind uvicorn, whose HTTP parser validates Content-Length first. It also contradicts the docstring's "huge numbers are never converted". Suggested fix: `stripped = value.lstrip(b"0"); ... return int(stripped or b"0")`, plus a test with 5000 leading zeros.
- [nit] app/middleware.py:163-169: once `exceeded` is set, any exception from the app is swallowed, even one that has nothing to do with the body limit. If the response had already started, the app returns with an incomplete response and nothing is logged. This is acceptable for this API (no streaming endpoints), but a one-line comment, or re-raising when `response_started` is True, would make the trade-off explicit.
- [nit] app/middleware.py:56-57: `PAYLOAD_TOO_LARGE_STATUS`/`PAYLOAD_TOO_LARGE_CODE` repeat the `413: "payload_too_large"` entry already in `app.errors._STATUS_CODES`. Consider `code_for_status(413)`, as the 400 path already does. The public `payload_too_large` next to the private `_invalid_content_length` is also slightly inconsistent naming.
- [nit] tests/test_middleware.py: no test asserts the `Connection: close` header on the 413/400 responses, even though it is a deliberate decision. Add an assertion to one Content-Length test and one streamed test.
