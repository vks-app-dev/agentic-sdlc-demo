## Evaluation of the coder's flagged decisions
1. Validated `amount` is a 2-decimal string: this matches ADR Context item 1 (`"12.5"` becomes `"12.50"`) and the TEXT storage in Option A. Accepted.
2. Control characters are checked before trimming, so tab and newline anywhere in a note are rejected: the ADR security review row says to reject `\x00-\x1f` and `\x7f-\x9f` in `category` and `note`, and that range includes `\t`, `\n` and `\r`. The implementation follows the approved ADR literally, and no acceptance test sends a note with a newline or tab, or a value with a leading or trailing control character. Checking before trimming is also the conservative choice, since `str.strip()` would otherwise silently drop `\x1c-\x1f` and `\x85`. Accepted. The product consequence, that notes cannot span several lines, should be stated for a human at the gate (see the nit below).
3. Custom error types without `ctx`: these are needed to keep messages fixed and to keep input out of `ctx`, and T2 never reads `ctx` anyway. Clients only see `field` and `message`, so the custom type names (`amount_invalid`, `control_characters`, ...) are not exposed. Reusing the built-in name `string_type` for a custom error is harmless. Accepted.
