Findings
- [nit] app/money.py:31 — `MONEY_CONTEXT` is a shared, mutable `Context`, and FastAPI's threadpool will set its `flags` from several threads. Traps do not depend on flags, so behaviour is correct. However, any later code that reads `MONEY_CONTEXT.flags` would see state from other threads. Suggested fix: add a comment saying flags must not be relied on, or never read them.
- [nit] app/money.py:76 — `format_amount` raises a raw `decimal.Inexact` (not `AmountError`) when given more than 2 decimals. This is reasonable as a programming-error signal, and the test pins it, but the docstring should say so. T7 must then only pass quantized or stored canonical values.
- [nit] app/money.py:89 — `create_decimal(raw)` on stored strings also accepts forms like "1_000", " 12.50 " or "NaN". This is harmless because only canonical strings written by `parse_amount` are stored. Optionally assert the canonical form, or document the assumption.
- [nit] tests/test_money.py:30 — `getcontext().prec == 28` assumes no other test or plugin has changed the thread's global context. It is fine today. A more robust check is that `MONEY_CONTEXT` is not `getcontext()` and that `decimal.DefaultContext.prec` is unchanged.
- [nit] tests/test_money.py:128 — the localcontext tests use a function-local `import decimal`, even though `decimal` names are already imported at module top. Hoist the import for consistency.
